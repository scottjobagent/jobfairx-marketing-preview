Hiring event calendar, rezi.ai direction: build notes for Brandon

Design reference for jobfairx.com/employer/hiring-event-calendar, built in the same system as the rezi-direction employer home page and the event page: rezi.ai's layout and feel (the pattern here is rezi's blog listing: eyebrow pill on a rule, headline 7/12 with the description 5/12, a chip filter row on rules, hairline rows), JobFairX colours, Inter and Inter Tight. Every word is the live calendar's copy and every row is a real event read from the live page on 22 Oct 2026 (the first 100 it lists: October 27 to November 18, 2026). Nothing is invented; the one new string is marked below.

What stays exactly as it is on the live page

  • Title, meta description and canonical. The H1 is still the small "2026 Hiring events" label (on the live page it is the eyebrow; here it is the eyebrow pill) and the H2 is "Interview-Ready Candidates Matched to Your Jobs" with the same sub-line.
  • The two controls: the city search with the live placeholder ("Search by city (e.g. Dallas, TX)") and the type filter with the live options in the live order (All Types, Diversity, Veterans, Healthcare, Entry Level, Technology), each with the live colour for that type.
  • The four columns (Date, City, Type, Candidate matching), the row content (date, "City, ST Hiring Event" linking to that event's live page, type, matching status "Live" or "Activates soon", View Details), the "Load More Events" button, the bundles card ("Interested in multiple events?" with its link), the phone-only "Looking for a job?" strip, the nav and the footer.
  • Keep the live page's JSON-LD ItemList and the load-more and filter behaviour on the server side; this file only demonstrates them on the 100 rows it holds.
  • Everything that changes with the data carries data-dynamic: the candidate-matching status pill (candidate-matching-status). The month groups, their counts and the "Showing x of y" line are computed from the rows.

What the design changes

  • Rows are hairline rows inside the container's two vertical rules (rezi), not bordered cards. 69px tall on desktop, stacked on phones with a chevron.
  • Rows are sorted by date and grouped by month, each group with its count (the live page lists them in a rotating-type order). Decision for Scott.
  • 30 rows per page, then "Load More Events" reveals 30 more (the live page shows 100). Page size is yours.
  • The type dropdown becomes a chip row (same options, same order, same colours). On narrow screens it scrolls sideways with a fade on the right edge, as rezi's does.
  • A "Showing 30 of 100 upcoming events" line above the columns, which rewrites itself as the filters change, and an empty state when nothing matches. New copy (change as you like): "No events match. Try another city or type, or clear the filters."
  • The closing band is shared with the employer home design; its button here goes to pricing/registration instead of back to this calendar.

Motion

The header fades and rises on load (rezi's power4 ease, replicated with cubic-bezier(.165,.84,.44,1)), the first rows rise in a 40 ms stagger, the Live dot pulses, and the bundles card reveals on scroll. All of it is off under prefers-reduced-motion.

Breakpoints

Above 1100px the search sits left of the chips. At 1100px and below the search takes its own line. At 900px and below the column headers go, each row becomes a stacked block (date and weekday, city, type and status chips, chevron), the bundles card stacks, and the navy "Looking for a job?" strip appears under the nav, as on the live phone layout.

System

Same tokens as the home design: #FAFAFA page, two vertical hairlines at the container edges, container margin clamp(0.75rem, 3.44vw - 0.095rem, 3rem), padding clamp(1.25rem, 3.82vw + 0.312rem, 3.75rem), pill buttons 48px (36px in rows), brand blue #0044B3 with the #E8EFFB tint, navy #00245B, the live type colours for the dots (#2563EB technology, #EA580C diversity, #0D9488 healthcare, #DC2626 veterans, #0284C7 entry-level), Live pill #E3F6EE/#146C43.

Decisions for Scott

  2. 30 rows per page or the live 100?
  3. Chips or keep the dropdown?
  4. Keep the closing band on this page, or end at the bundles card?
  5. The toolbar is not sticky here; should it stick under the nav while scrolling the list?
  6. The empty-state wording (new copy).
  7. Should the big headline become the H1 (SEO question for Michael)? The live page keeps the H1 on the small label.
