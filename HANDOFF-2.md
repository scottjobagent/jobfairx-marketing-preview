## 1. Executive overview

**JobFairX** runs hiring events (NOT a job board — non-negotiable in all copy). Employers
register for an event, post jobs, AI matches registered candidates, candidates **request**
interviews, the employer **accepts/declines/proposes times**. Interviews run **in person / on
JobFairX video / by phone / on the employer's own link** — chosen per event at Interview
Settings. **In-person is the market priority, video second; phone real but deliberately
downplayed in marketing.** External link is a sub-choice *inside* Video (JobFairX native vs
third-party), per `setup-flow-v3.html`.

**Scott** (scott@jobfairx.com, GitHub `scottjobagent`) — founder; voice-dictated messages
(expect transcription noise); green-light workflow: **show design examples in chat → he
approves → implement → verify on the real DOM → push → verify at SHA + plain URL**. Give
recommendations, not menus. Report failures plainly. Placeholders for unknowns — never invent
numbers, quotes, or features.

**Business goals this session served:** (1) reflect the in-person/video/phone launch across
marketing; (2) make the marketing site tell the complete product story (automations, analytics,

## 9. Lessons learned / dead ends (do not repeat)

- **Purged Tailwind:** the live site's compiled CSS lacks any utility the live pages never used
  (`right-2.5`, `grid-cols-4` bit us). For new markup in the marketing pages, use **inline
  styles or a scoped `<style>` block** (bento pattern) — never bare utilities.
- **Deep-route relative hrefs:** partial-string substitution on URLs corrupted CSS paths
  (`../../../.assets/`). Replace full captured hrefs.
- **Zero-match `sub()` must abort** — a count-derived expected value of 0 passed silently
  (double-space in the live title).
- **JS-dependent markup ships dead** through the static pipeline (scroll-pinned sections, FAQ
  accordion). Rule: the designed state is the only state; native elements (`<details>`) over JS.
- **Verify total page height**, not just strings/images (the 82k-px page passed my
  string checks).
- **The browser pane shares one HTTP cache across tabs** — a "new tab" is not a clean client;
  Pages caches 600s. Verify freshness with curl + a build-unique discriminator.
- **GitHub upload clicks can silently fail** (head didn't move once); always confirm the SHA.
- **Regex spans over JS functions truncate** (non-greedy hit the `for`-loop brace) — brace-match
  or exact-line edits.
- **CSS orphan-selector fusion:** regex-deleting `sel a{...}` rules left `.tl-s.done .tl-m`
  prefixes that fused with following rules and silently broke a media query. Don't
  pattern-delete CSS; leave dead rules inert or parse properly. (Dead `.tl-*` rules still in the
  seeker file, harmless.)
- Live page's `<h1>` is the little eyebrow, not the big headline (a styled div) — SEO edits and
  visual edits are different nodes.
- The scheduling-tracking strings on the live marketing site don't exist in the product — check
  the app before reusing marketing copy as "product truth".
- Measure candidate headlines at the exact rendered font before proposing (canvas measureText).
